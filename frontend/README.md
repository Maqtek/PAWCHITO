# PAWCHITO — фронтенд

React 19 + TypeScript + Vite. Стили — Tailwind 4, данные — TanStack Query и openapi-fetch, моки — MSW.

## Запуск

```bash
pnpm install
pnpm dev
```

Откройте http://localhost:5173. По умолчанию фронтенд отправляет запросы `/api` на реальный бэкенд через прокси Vite (`http://localhost:8000`).

Для разработки без готового бэкенда необходимо включить моки MSW с помощью `VITE_MOCKS=true`. В этом режиме MSW перехватывает запросы к эндпоинтам, для которых предусмотрены обработчики в `src/mocks/handlers`. Запросы без обработчиков передаются через прокси Vite с предупреждением в консоли браузера.

### Вход и сессия на моках

Моки — мини-сервер с состоянием в `localStorage` (общий для вкладок). Первый запуск — гость, открывается `/login`;
Там «Моки: войти как» выполняет вход под тестовым аккаунтом через POST /api/auth/login, который перехватывается MSW. 
«Сбросить моки» восстанавливает исходные тестовые данные.

Экраны авторизации: `/login`, `/register`, `/recover`. После регистрации и восстановления показывается код
восстановления — без отметки «Код сохранён в надёжном месте» дальше не пройти. Проверить восстановление:
owner@example.com и код `K7QM-2XPA-9RTD-4WNB` (регистр и дефисы не важны). Восстановление меняет и пароль, и код:
дальше владелец входит новым паролем, а кнопка «Владелец» в «Моки: войти как» не войдёт. «Сбросить моки» вернёт seed —
и код, и пароль `pawchito1`.

Профиль (`/profile`, меню пользователя → «Профиль»): имя меняется на месте, «Сменить пароль» завершает остальные
сессии, у владельца — «Новый код восстановления» (старый код перестаёт действовать). Клиника с временным паролем
(clinic-new@example.com) после входа попадает на `/change-password` и до смены пароля другие разделы не видит.

Админка (`/admin/clinics`, вход «Администратор»): список клиник с вкладками «Активные» и «Скрытые» и поиском,
страница клиники — данные и их изменение, аккаунт (создание, сброс пароля — временный пароль показывается один раз),
скрытие и возврат. Seed: «ВетДоктор» (аккаунт clinic@example.com, 7 будущих записей), «Клиника «Новая»»
(clinic-new@example.com, временный пароль), «Зоовет» (без аккаунта), скрытая «Айболит» (aibolit@example.com
заблокирован). Записей в моках пока нет — число отменяемых при скрытии хранится в клинике. Состояние моков до этапа 3
(без клиник) при первом запуске заменяется seed.

Врачи (`/clinic/vets`, вход «Клиника»): вкладки «Активные» и «Архив», добавление и изменение (ФИО, специализация),
отпуск — флаг без дат (Р-37), ставится и снимается кнопкой в карточке; архив и возврат — с подтверждением. Seed
«ВетДоктора»: Петров (терапевт), Соколова (хирург, в отпуске), Ким (без специализации), Орлов в архиве. У «Зоовета» —
Белова: clinic@example.com её не видит, изменить не может (`404`, как у несуществующего врача). Состояние моков без
врачей (до этапа 4) получает seed-врачей при первом запуске.

Питомцы (`/pets`, вход «Владелец»): список в порядке добавления с иллюстрацией по виду, «Выбрать» — тот же выбор, что в
переключателе в шапке; добавление (новый питомец сразу выбран) и изменение — кличка, вид, порода, дата рождения, пол;
архив — с подтверждением. Просмотра архива и возврата из него в MVP нет (Р-40): питомец просто пропадает из списка и
переключателя. Seed владельца: Майло (собака, на лечении в «ВетДокторе») и Барсик (кошка), попугай Кеша в архиве. Рекс —
питомец другого владельца: owner@example.com его не видит и не меняет (`404`). Архив отменяет будущие записи питомца
и удаляет его запланированные дела (Р-02). Состояние моков без питомцев (до этапа 5) получает seed-питомцев при первом
запуске.

История (`/history`, вход «Владелец»): для выбранного питомца — особенности здоровья (добавление, изменение, архив),
дневник (новые наблюдения сверху, свои можно исправить — удаления нет, Р-43) и прививки из ветпаспорта (добавление,
изменение, удаление; просроченная отмечена). Записи клиники — только для чтения, с меткой «Внесено клиникой». Seed Майло:
аллергия на курицу (своя) и дисплазия (от клиники), три наблюдения — одно с весом с приёма, прививки Rabies (своя) и
DHPPi (от клиники). У Барсика — одно наблюдение и просроченная прививка, особенностей нет. Лента истории — этап 11.

Записи к врачу (`/appointments`, вход «Владелец»): для выбранного питомца — предстоящие (по времени, с отменой до начала
приёма, Р-48) и прошедшие и отменённые; карточка записи — `/appointments/:id`. «Записаться к врачу» (`/appointments/new`)
— мастер: клиника → врач (без отпуска и архива) → дата и свободное время (по 30 минут, на 30 дней вперёд) → причина,
комментарий и питомец. Занятое время, пока заполняли причину, — назад к выбору времени. Seed считается от сегодняшнего
дня, поэтому предстоящие записи не устаревают: у Майло — подтверждённая вакцинация через 2 дня и заявка через 5,
завершённый приём 16 дней назад и запись, отменённая клиникой; у Барсика — заявка на завтра. Рядом с записью Майло у
Петрова — запись чужого Рекса: этот слот занят. Архив питомца и скрытие клиники отменяют будущие записи (`system`).

Записи клиники (`/clinic/appointments`, вход «Клиника»): вкладки «Расписание» (неделя с сегодняшнего дня, фильтры
по датам, врачу и статусу — в адресе страницы), «Ждут итога» и «Требуют решения» (будущие записи врача в отпуске или
архиве) с числами. Заявку до начала приёма подтверждают кнопкой, запись отменяют с обязательным комментарием владельцу —
в том числе прошедшую (неявка, Р-53). Карточка питомца (`/clinic/pets/:petId`) — только
чтение: данные, особенности здоровья, прививки, дневник владельца и приёмы в этой клинике; без неотменённой записи
к вам — «Карточка недоступна» (Р-54).

Итог приёма — кнопка «Внести итог» у подтверждённой записи, время которой наступило (вкладка «Ждут итога»): заключение,
рекомендации, статус ухода, рецепты, прививки, особенности здоровья и данные питомца (вес, порода, дата рождения, пол —
уходят только изменённые) одной формой; после сохранения итог не меняется. По каждому рецепту владелец получает дела
курса на каждый день и время, кроме уже прошедших (Р-56), и видит итог на странице записи. Изменения карточки клиникой
(Р-57) и фото (Р-58) доступны только после завершённого приёма в этой клинике; владелец получает уведомление, что
изменено. Фото — кнопка «Загрузить фото» в карточке питомца: JPEG, PNG или WebP до 5 МБ, тип проверяется по
содержимому; моки хранят фото как `data:`-адрес в своём состоянии. В seed подтверждённые приёмы ещё впереди — чтобы
проверить итог, выполните в консоли `pawchitoMocks.startVisit()`: запись Майло переедет на текущие полчаса.

Дела (`/tasks`, вход «Владелец»): для выбранного питомца — запланированные просроченные и на неделю вперёд по времени,
«Показать ещё неделю» расширяет период (группы «Сегодня / Завтра / Позже», записи и сроки прививок — этап 11).
Отметить можно дело на сегодня и просроченное (Р-61): «Выполнено» — одной кнопкой, «Пропустить» — с подтверждением,
отметка окончательная; у дела с повтором сервер сразу создаёт следующее — от плановой даты. «Добавить дело» — своё дело:
название, дата и время (от текущей минуты до года вперёд), тип (по умолчанию «Уход»), повтор — каждый день, раз в 7, 14,
30 дней или свой интервал (Р-59). Удалить можно только своё запланированное дело — с ним заканчивается серия; дела курса
не удаляются (Р-62). Курс лечения (`/course`): курсы из итогов приёмов питомца (Р-63) — у активного прогресс («5 из 14
выполнено, 1 пропущено») и дни с дозами с первой неотмеченной, прошедшие дни — под кнопкой; у завершённого — только
прогресс. Seed: у Майло курс Мелоксикама в 20:00 на 21 день с завершённого приёма 16 дней назад — до позавчера
выполнен, одна доза пропущена, вчерашняя просрочена; «Купить корм» сегодня в 18:00 и «Почистить зубы» раз в неделю
(завтра в 21:00). У Барсика — «Капли от блох» раз в 30 дней через 3 дня. Сохранённое состояние моков до этапа 10
получит seed-дела, но не рецепт в итоге приёма — чтобы курс появился и в «Курсе лечения», выполните
`pawchitoMocks.reset()`.

Уведомления (колокольчик в шапке, владелец и клиника): последние 50, непрочитанные выделены, переход по уведомлению
отмечает его прочитанным, есть «Прочитать все»; число непрочитанных опрашивается раз в минуту. Владельцу ссылка ведёт
на страницу записи, клинике — на день приёма в записях (Р-55). Seed: у владельца три непрочитанных и два прочитанных, у
«ВетДоктора» — две непрочитанные заявки. Новые уведомления создают запись и отмена владельцем, архив питомца,
подтверждение и отмена клиникой, итог приёма и изменения карточки клиникой (ссылка — на «Мои питомцы»), скрытие
клиники.

|---|---|---|

| clinic@example.com | клиника | — |

Пароль seed-аккаунтов — `pawchito1` (у владельца — пока не восстановили доступ). После 5 неудачных попыток входа,
восстановления, смены пароля или получения нового кода (счётчик общий на аккаунт) — пауза 15 минут (`429`).

Лимиты полей — в `src/api/limits.ts`: email до 254 символов, имя от 1 до 100, пароль от 8 до 128 (длина — в символах
Unicode, как `len()` в Python; `maxLength` в полях считает в UTF-16 и режет чуть раньше сервера). Клиника
(`clinicLimits`): название до 100, адрес до 200, телефон `+7` и 10 цифр, часы с шагом 30 минут в пределах суток —
контракты, раздел 9 «Лимиты полей клиники». Врач (`vetLimits`): ФИО от 1 до 100, специализация необязательна, до 100,
пустая сохраняется как `null` — контракты, раздел 5 «Лимиты полей врача». Питомец (`petLimits`): кличка от 1 до 50,
вид обязателен, порода необязательна, до 100, дата рождения необязательна, с 1900-01-01 по сегодня по Москве, пол по
умолчанию «Не указан» — контракты, раздел 2 «Лимиты полей питомца». Здоровье (`healthLimits`): название особенности
и прививки до 100, комментарий и заметка до 1000, симптомы до 500, вес от 0,1 до 200 кг (вводится с запятой), даты — с
1900-01-01 по сегодня по Москве, следующая прививка позже даты прививки — контракты, раздел 3 «Лимиты полей здоровья».
Запись (`appointmentLimits`): комментарий до 500, окно — 30 дней, слот — 30 минут — контракты, раздел 4 «Лимиты полей
записи». Итог приёма (`outcomeLimits`): заключение от 1 до 2000, рекомендации до 2000; рецептов до 10 (препарат и
дозировка до 100, от 1 до 6 разных времён `ЧЧ:ММ`, курс от 1 до 90 дней, начало — от дня приёма до 30 дней после),
прививок и особенностей — до 5 (дата прививки — от дня приёма до сегодня); фото до 5 МБ — контракты, раздел 5 «Лимиты
полей итога». Ошибки строк приходят с индексом в `loc` (`body.prescriptions.0.times`) — форма показывает их у полей
нужной строки через `ApiError.pathErrors`. Своё дело (`reminderLimits`): название от 1 до 100, дата и время — от текущей
минуты до сегодня + 365 дней по Москве, повтор — от 1 до 365 дней — контракты, раздел 6 «Лимиты полей дела».
На нарушение моки отвечают `422` в формате FastAPI, как будет отвечать бэкенд: пустое имя, имя с управляющими символами,
слишком длинные строки, поле не строкой, тело не JSON. HTML в имени сохраняется как текст — React выводит его экранированным.

Команды в консоли браузера. Счётчик уведомлений (владелец и клиника) опрашивает сервер раз в минуту — после команды
подождите до минуты или перезагрузите данные страницы, и приложение само сходит в `/api/auth/refresh` (видно во вкладке Network).

| Команда | Что проверяет |
|---|---|
| `pawchitoMocks.expireAccess()` | «прошло 15 минут»: следующий запрос получит 401, приложение молча обновит токен |
| `pawchitoMocks.endSessions()` | сервер завершил сессии: следующий запрос уведёт на `/login` с «Сессия истекла — войдите снова» |
| `pawchitoMocks.requirePasswordChange()` | «администратор сбросил пароль» вошедшему аккаунту: следующий запрос уведёт на `/change-password` |
| `pawchitoMocks.startVisit()` / `(id)` | «приём начался»: подтверждённая запись (по умолчанию №20, Майло) переезжает на текущие полчаса и ждёт итога; обновите список записей |
| `pawchitoMocks.network(false)` / `(true)` | сеть моков (режим Offline в DevTools не помогает — MSW отвечает из service worker); событие `online` получает только вкладка, где выполнена команда, — вызывайте там, где ждёт выход |
| `pawchitoMocks.reset()` | вернуть seed; после этого перезагрузите открытые вкладки — токен в памяти вкладки сбросом не стирается |

Как проверить вкладки: откройте две вкладки владельцем, выполните `pawchitoMocks.expireAccess()` и подождите минуту —
обе обновят токен по очереди, никого не выкинет; «Выйти» в одной вкладке уводит на `/login` и вторую;
вход во второй вкладке переводит первую из `/login` в кабинет.

### Переключение между моками и реальным API

По умолчанию фронтенд PAWCHITO работает с реальным API. Для разработки и тестирования без готового бэкенда используется MSW (Mock Service Worker).

**Запуск с моками**

Создайте файл `frontend/.env.local` и укажите:

```dotenv
VITE_MOCKS=true
```

Запустите фронтенд из папки `frontend`:

```bash
pnpm dev
```

MSW будет перехватывать запросы к реализованным моковым эндпоинтам. Это позволяет тестировать авторизацию, регистрацию, восстановление пароля и пользовательские кабинеты без реального сервера.

**Запуск с реальным API**

Для работы с настоящим бэкендом укажите в `frontend/.env.local`:

```dotenv
VITE_MOCKS=false
```

Либо удалите переменную. Запросы `/api` будут направляться через прокси Vite на `http://localhost:8000`. Бэкенд должен быть запущен.

**Запуск через Docker**

Для использования моков при запуске через Docker Compose добавьте в корневой `.env`:

```dotenv
VITE_MOCKS=true
```

По умолчанию в Docker моки отключены. Адрес бэкенда задаётся переменной `API_PROXY_TARGET`.

**Текущее состояние проекта**

Часть серверных эндпоинтов пока не реализована. Для проверки соответствующих экранов необходимо использовать `VITE_MOCKS=true`.
В частности, это касается админки клиник из PR #83: списка клиник, управления аккаунтами и сброса паролей.
После изменения переменных окружения необходимо перезапустить Vite.

### Генерация типов API

Типы эндпоинтов, реализованных на бэкенде, генерирует `openapi-typescript` из `backend/openapi.json`
в `src/api/generated/schema.ts`. Файл лежит в репозитории и руками не правится: после изменения `openapi.json`
выполните из папки `frontend` и закоммитьте результат:

```bash
pnpm gen:api
```

CI перегенерирует файл и падает, если он отличается от закоммиченного.

Код по-прежнему импортирует типы из `src/api/schema.ts`. Там `paths` клиента — сгенерированные пути, поверх которых
ручные (по контрактам) для эндпоинтов, которых на бэкенде ещё нет. Из сгенерированных сейчас: `/auth/login`,
`/auth/refresh`, `/auth/logout`, `/auth/change-password`, `/auth/recover`, `/users/me/recovery-code`, тела запросов
авторизации и профиля, ответ `422`, роль и `Token`. `/auth/register` и `/users/me` пока ручные: по контракту
`full_name` у `User` — строка, а бэкенд отдаёт `string | null` (у аккаунта клиники имени нет). Когда бэкенд
реализует эндпоинт, его ручной путь из `src/api/schema.ts` удаляется.

## Устройство

- `src/api/schema.ts` — типы по `docs/Контракты_Pawchito.md`. Когда бэкенд отдаст `openapi.json`, файл заменяется генерацией `openapi-typescript`.
- `src/api/auth-token.ts` — access-токен, только в памяти (не в `localStorage`).
- `src/api/session.ts` — сессия: refresh-cookie → токен до первого запроса, обмен по очереди между вкладками (`navigator.locks`), вход и выход во всех вкладках (`BroadcastChannel`), выход без сети доводится позже.
- `src/api/client.ts` — клиент openapi-fetch: ждёт сессию, подставляет токен, на 401 обновляет его и повторяет запрос; не вышло — экран входа.
- `src/api/error-messages.ts` — тексты ошибок для форм и причин выхода.
- `src/mocks/` — мок-сервер по контрактам (`server-state.ts`, `handlers/`); новый эндпоинт → тип в `schema.ts` + обработчик в `mocks/handlers`.
- `src/components/ui/` — UI-кит; цвета и радиусы — только токены из `src/styles/index.css`.
- `src/lib/labels.ts` — подписи значений по глоссарию; в интерфейсе не пишем значения enum напрямую.
- `src/app/navigation.ts` — разделы по ролям (бизнес-правила, §11).
- `src/lib/use-form.ts` — хук форм: ошибки полей при отправке и дальше живьём, фокус на первое неверное поле, 422 по полям.
- `src/features/auth/` — проверки полей авторизации, экран кода восстановления, форма смены пароля; `src/pages/auth/` — вход, регистрация, восстановление, смена временного пароля.
- `src/features/profile/` — имя на месте и модалки профиля (смена пароля, новый код восстановления).
- `src/features/admin/` — форма клиники, секции страницы клиники, временный пароль; `src/pages/admin/` — список и страница клиники.
- `src/features/vets/` — карточка врача с отпуском, форма врача, подтверждение архива и возврата; `src/pages/clinic/ClinicVetsPage.tsx` — врачи клиники.
- `src/features/pets/` — выбранный питомец, карточка в списке, форма питомца, подтверждение архива; `src/pages/owner/PetsPage.tsx` — питомцы владельца.
- `src/features/health/` — разделы «Истории» (особенности, дневник, прививки), их формы и подтверждение; `src/pages/owner/HistoryPage.tsx` — история выбранного питомца.
- `src/features/appointments/` — мастер записи, карточка записи, подтверждение отмены; `src/pages/owner/` — `AppointmentsPage` (мои записи), `NewAppointmentPage`, `AppointmentPage`. Даты по Москве — `src/lib/dates.ts`.
- `src/features/clinic-appointments/` — запись в кабинете клиники, отмена с комментарием; `src/pages/clinic/` — `ClinicAppointmentsPage` и карточка `ClinicPetPage`.
- `src/features/notifications/` — список уведомлений в выпадающей панели колокольчика (`src/layouts/NotificationBell.tsx`); тексты и ссылки уведомлений моков — `src/mocks/notification-texts.ts`.
