# PAWCHITO — фронтенд

React 19 + TypeScript + Vite. Стили — Tailwind 4, данные — TanStack Query и openapi-fetch, моки — MSW.

## Запуск

```bash
pnpm install
pnpm dev
```

Откройте http://localhost:5173. В разработке моки MSW отвечают на эндпоинты, для которых есть обработчики
в `src/mocks/handlers`; остальные запросы `/api` уходят в прокси Vite на `http://localhost:8000`,
а в консоли браузера появляется предупреждение MSW о запросе без мока.

### Вход и сессия на моках

Моки — мини-сервер с состоянием в `localStorage` (общий для вкладок). Первый запуск — гость, открывается `/login`;
там «Моки: войти как» входит seed-аккаунтом через настоящий `POST /auth/login`. «Сбросить моки» возвращает seed.

Экраны авторизации: `/login`, `/register`, `/recover`. После регистрации и восстановления показывается код
восстановления — без отметки «Код сохранён в надёжном месте» дальше не пройти. Проверить восстановление:
owner@example.com и код `K7QM-2XPA-9RTD-4WNB` (регистр и дефисы не важны). Восстановление меняет и пароль, и код:
дальше владелец входит новым паролем, а кнопка «Владелец» в «Моки: войти как» не войдёт. «Сбросить моки» вернёт seed —
и код, и пароль `pawchito1`.

| Email | Роль | Особенность |
|---|---|---|
| owner@example.com | владелец | код восстановления `K7QM-2XPA-9RTD-4WNB` |
| clinic@example.com | клиника | — |
| clinic-new@example.com | клиника | временный пароль, нужно сменить |
| admin@example.com | администратор | — |
| blocked@example.com | владелец | заблокирован |

Пароль seed-аккаунтов — `pawchito1` (у владельца — пока не восстановили доступ). После 5 неудачных попыток входа
или восстановления — пауза 15 минут (`429`).

Лимиты полей — в `src/api/limits.ts`: email до 254 символов, имя от 1 до 100, пароль от 8 до 128 (эмодзи — один символ).
На нарушение моки отвечают `422` в формате FastAPI, как будет отвечать бэкенд: пустое имя, имя с управляющими символами,
слишком длинные строки, поле не строкой, тело не JSON. HTML в имени сохраняется как текст — React выводит его экранированным.

Команды в консоли браузера. Счётчик уведомлений (владелец и клиника) опрашивает сервер раз в минуту — после команды
подождите до минуты или перезагрузите данные страницы, и приложение само сходит в `/api/auth/refresh` (видно во вкладке Network).

| Команда | Что проверяет |
|---|---|
| `pawchitoMocks.expireAccess()` | «прошло 15 минут»: следующий запрос получит 401, приложение молча обновит токен |
| `pawchitoMocks.endSessions()` | сервер завершил сессии: следующий запрос уведёт на `/login` с «Сессия истекла — войдите снова» |
| `pawchitoMocks.network(false)` / `(true)` | сеть моков (режим Offline в DevTools не помогает — MSW отвечает из service worker); событие `online` получает только вкладка, где выполнена команда, — вызывайте там, где ждёт выход |
| `pawchitoMocks.reset()` | вернуть seed; после этого перезагрузите открытые вкладки — токен в памяти вкладки сбросом не стирается |

Как проверить вкладки: откройте две вкладки владельцем, выполните `pawchitoMocks.expireAccess()` и подождите минуту —
обе обновят токен по очереди, никого не выкинет; «Выйти» в одной вкладке уводит на `/login` и вторую;
вход во второй вкладке переводит первую из `/login` в кабинет.

### Настоящий бэкенд вместо моков

Запросы пойдут на `http://localhost:8000` через прокси Vite. Способ для любой ОС, включая Windows, —
создать `frontend/.env.local` (файл в `.gitignore`) и перезапустить `pnpm dev`:

```dotenv
VITE_API_MOCKS=false
```

Чтобы вернуть моки, удалите строку или файл. В bash/zsh можно и разово, без файла:

```bash
VITE_API_MOCKS=false pnpm dev
```

## Устройство

- `src/api/schema.ts` — типы по `docs/Контракты_Pawchito.md`. Когда бэкенд отдаст `openapi.json`, файл заменяется генерацией `openapi-typescript`.
- `src/api/auth-token.ts` — access-токен, только в памяти (не в `localStorage`).
- `src/api/session.ts` — сессия: refresh-cookie → токен до первого запроса, обмен по очереди между вкладками (`navigator.locks`), вход и выход во всех вкладках (`BroadcastChannel`), выход без сети доводится позже.
- `src/api/client.ts` — клиент openapi-fetch: ждёт сессию, подставляет токен, на 401 обновляет его и повторяет запрос; не вышло — экран входа.
- `src/api/error-messages.ts` — тексты ошибок для форм и причин выхода.
- `src/mocks/` — мок-сервер по контрактам (`server-state.ts`, `handlers/`); новый эндпоинт → тип в `schema.ts` + обработчик в `mocks/handlers`.
- `src/components/ui/` — UI-кит; цвета и радиусы — только токены из `src/styles/index.css`.
- `src/lib/labels.ts` — подписи значений по глоссарию; в интерфейсе не пишем значения enum напрямую.
- `src/app/navigation.ts` — разделы по ролям (бизнес-правила, §11).
- `src/lib/use-form.ts` — хук форм: ошибки полей при отправке и дальше живьём, фокус на первое неверное поле, 422 по полям.
- `src/features/auth/` — проверки полей авторизации и экран кода восстановления; `src/pages/auth/` — вход, регистрация, восстановление.
