# PAWCHITO — роадмап

back — Вдовин, Пугно · front — Еременко, Черников · devops — Черников

Фронт и бэк идут параллельно: бэк отдаёт `openapi.json`, фронт работает на моках.

## Этап 1. Каркас

- (devops) Репозиторий, `.env.example`, защита `main`.
- (devops) Docker Compose: PostgreSQL, Redis, бэк, фронт.
- (devops) Redis: AOF, `maxmemory` 256 МБ.
- (devops) CI: ruff, mypy, pytest, eslint, сборка, миграции с нуля + `alembic check`.
- (back) FastAPI: routers → services → repositories → models.
- (back) SQLAlchemy, `BaseRepository`.
- (back) Alembic: `naming_convention`, `upgrade head` при старте контейнера; дальше каждый этап — своя миграция.
- (back) Логи в Redis Stream: запросы, события, ошибки, `request_id`; без Redis — в stdout.
- (front) React + TS + Vite, роутинг, layout, моки MSW.
- (front) UI-кит.

**Итог:** `docker compose up` поднимает пустое приложение, миграции применяются, логи пишутся в Redis.

## Этап 2. Аккаунт и роли

- (back) Миграция `users`; регистрация, вход, JWT, Argon2.
- (back) Проверка роли, админ из seed.
- (front) Вход, регистрация, разделы по ролям.
- (back) Тесты доступа.

**Итог:** владелец регистрируется, каждая роль видит свой раздел.

## Этап 3. Клиники

- (back) Миграция `clinics`; добавление, изменение, скрытие.
- (back) Создание аккаунта клиники.
- (front) Админка: клиники и аккаунты.

**Итог:** админ создаёт клинику и её аккаунт.

## Этап 4. Врачи

- (back) Миграция `vets`; добавление, изменение, удаление, отпуск.
- (front) Страница врачей в кабинете клиники.

**Итог:** клиника ведёт врачей и отпуска.

## Этап 5. Питомцы

- (back) Миграция `pets`; CRUD, проверка владельца.
- (front) Список, переключатель, формы.

**Итог:** владелец ведёт нескольких питомцев.

## Этап 6. Памятка

- (back) Миграция `pet_conditions`, `observations`, `vaccinations`.
- (back) Представление `pet_timeline` — в миграции вручную.
- (front) Памятка: здоровье, дневник, лента, прививка из ветпаспорта.

**Итог:** владелец ведёт дневник питомца.

## Этап 7. Запись к врачу

- (back) Миграция `appointments`, частичный индекс на слот врача.
- (back) Свободные слоты по 30 мин, запись, отмена.
- (front) Мастер записи, мои записи.
- (back) Тесты слотов и двойной записи.

**Итог:** владелец записывается на свободное время.

## Этап 8. Кабинет клиники

- (back) Подтверждение, перенос, отмена записи.
- (back) Записи врача в отпуске, карточка питомца для клиники.
- (front) Записи с фильтрами, действия, карточка питомца.
- (back) Тесты статусов и доступа.

**Итог:** клиника управляет записями.

## Этап 9. Итог приёма

- (back) Миграция `prescriptions`; завершение приёма одной транзакцией.
- (back) Статус ухода питомца выставляется при итоге приёма.
- (front) Форма итога: заключение, рецепты, прививки, статус ухода.
- (front) История приёмов у владельца.

**Итог:** владелец видит итог приёма и статус ухода.

## Этап 10. Напоминания

- (back) Миграция `reminders`; дозы курса из рецепта.
- (back) Свои дела с повтором, отметка выполнения.
- (front) Список дел, отметка, своё дело.
- (back) Тесты генерации напоминаний.

**Итог:** после приёма появляются напоминания по курсу.

## Этап 11. Главная и календарь

- (back) Представление `calendar_events` в миграции; сводка, прогресс курса.
- (front) Главная: питомец и статус ухода, прогресс, дела на сегодня.
- (front) Календарь: сегодня / завтра / позже, фильтры.

**Итог:** видно, что делать сейчас и дальше.

## Этап 12. Релиз

- (devops) VPS, Caddy + HTTPS.
- (devops) Деплой из GitHub Actions: `pg_dump` → `alembic upgrade head` → перезапуск.
- (devops) Ежедневный `pg_dump`; логи в Redis — 14 дней.
- (back) Демо-данные.
- (front, back) Прогон тест-кейсов.

**Итог:** рабочая версия по HTTPS.
