# PAWCHITO — требования

## 1. Анализ

- **Проблема:** данные о здоровье питомца разбросаны, владелец забывает дозы и прививки, запись — по телефону.
- **Решение:** единая медкарта: владелец ведёт историю и записывается к врачу, клиника вносит итог приёма, система сама создаёт напоминания. Диагнозы не ставит.
- **Роли:** владелец, клиника (врач без своего входа), администратор.
- **Входит:** питомцы, дневник, запись к врачу, кабинет клиники, итог приёма, напоминания, календарь, админка.
- **Не входит:** диагностика, оплата, чат, push / email / Telegram, вход врача, вложения, мобильное приложение.
- **Решения:** отпуск — флаг `on_vacation`; слот — 30 мин; врача с историей не удаляем; уведомления — внутри бэкенда.

**Риски**

| Риск | Мера |
|---|---|
| фронт и бэк разойдутся | контракт `openapi.json`, CI |
| не хватит времени | этапы по фичам; первыми резать фильтры календаря и перенос записи |

## 3. Системные требования

- **Безопасность:** пароли — Argon2; JWT на всех запросах, кроме входа; HTTPS; доступ проверяется на сервере.
- **Надёжность:** целостность на уровне БД; итог приёма — одна транзакция; ежедневный бэкап.
- **Логи:** Redis Stream, хранение 14 дней; без паролей, токенов и медданных.
- **Скорость:** ответ API ≤ 500 мс.
- **Удобство:** русский интерфейс, адаптив от 360 px.
- **Сопровождаемость:** слои бэкенда, линтеры и тесты в CI, актуальный `openapi.json`, схема БД — только миграциями Alembic.
- **Развёртывание:** `docker compose up`.
- **Сервер:** Linux VPS, 2 vCPU, 2 ГБ RAM, Docker, домен; PostgreSQL и Redis — в контейнерах.
- **Клиент:** актуальные Chrome, Firefox, Edge, Safari.

## 4. Несистемные требования

- Команда из 4 человек: back, front, devops.
- Работа по роадмапу, фронт и бэк параллельно.
- Git: ветка на задачу, PR с ревью, зелёный CI, без пушей в `main`.
- Задачи — в GitHub Projects.
- Схема БД меняется миграциями Alembic через Пугно, API — через контракт.
- Платные ресурсы — только VPS и домен.
- В репозитории нет реальных персональных данных.
